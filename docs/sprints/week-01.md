# Week 1: Architecture and infrastructure

## Goal

A repository that anyone can clone and run with `docker compose up`, plus the
architectural decisions that later weeks build on.

## Delivered

- [x] Repository, licence, contribution guide, editor and git settings
- [x] Functional and non-functional requirements (`docs/requirements.md`)
- [x] Architecture overview with module rules, request lifecycle and risks
- [x] ADR-001 (modular monolith) and ADR-002 (shared DB + RLS)
- [x] Database design (`docs/database/`), with RLS behaviour validated on

- [x] Initial privacy and threat model

- [x] Alembic baseline migration (extensions + tenant-context functions)
- [x] Pytest suite for configuration and health endpoints
- [x] GitHub Actions: ruff, mypy, pytest against a real PostGIS service

## Decisions made during the week

- **Driver**: psycopg 3 for both async SQLAlchemy and Alembic. One driver
  means one set of connection semantics to reason about.
- **IDs**: UUIDs generated by PostgreSQL (`gen_random_uuid()`, built in since
  PostgreSQL 13). This avoids enumeration and lets the mobile app reference
  records created offline.
- **Four tables beyond the brief**: `institution_memberships`,
  `platform_admins`, `classroom_teachers` and `attendance_subject_states`
  (reasons in `docs/database/schema.md`).
- **No empty modules**: business modules appear when they get their first
  feature (the brief asks to avoid empty placeholders).

## Missing requirements and risks found

1. **Clock trust**: the 15 s maximum request age assumes accurate phone
   clocks. Proposal: store both clocks, expose `GET /time`, and allow a
   small skew tolerance.
2. **Indoor GPS accuracy** often exceeds 30 m. Proposal: flag such events
   for review instead of rejecting them, and make thresholds per-institution
   settings.
3. **Young children without phones**: teacher-driven manual attendance is
   core for primary schools, not just a fallback.
4. **Polygon vs radius geofences**: the brief mentions both a 100 m radius
   and polygons. Proposal: polygons in storage; the admin UI can generate a
   polygon from a centre and radius (decided in ADR-003).
5. **Retention period** for coordinates needs a decision and a legal check.
6. **Choosing the institution** for users with several memberships:
   proposal is an `X-Institution-Id` hint, validated against memberships.
